## Codebase Patterns

- 2026-09-20 — Per-PR aggregation across multiple agent runs (e.g. summing cost) should query `agent_runs` directly (it has a nullable `prId` FK) rather than mirroring the "latest row wins" pattern `pulls/routes.ts`'s existing Score column uses over `reviews`. The `reviews` table has no duration/tokens/cost columns at all — those live only on `agent_runs`, joined to a review via `reviews.runId` (no FK constraint, just a plain uuid column). (`server/src/modules/pulls/routes.ts`, `server/src/modules/reviews/repository/run.repo.ts`)
- 2026-09-28 — When you need to add a field to a GET response and AGENTS.md's "do not touch `server/src/vendor/shared`" blocks extending the obvious Zod contract, check whether that specific `app.get(...)` registration even declares a `schema: { response: ... }` block first. `GET /repos/:id/pulls` (`server/src/modules/pulls/routes.ts:33`, no response schema — only `schema: { params: IdParams }`) has no runtime serialization stripping extra keys, so a locally-defined intersection type (`PrMetaWithFindings = PrMeta & {...}`, same file, line ~15) is enough — no vendor edit, no `.extend()` on the imported schema needed. This only works because THIS route has no response schema; don't assume it generalizes to routes that do declare one.
- 2026-10-01 — When you extract a route handler's inline Drizzle calls into a `repository.ts` (adding the route→service→repository layering to a module that lacked it), also check whether the original code did 2+ dependent writes without a transaction — the layering refactor doesn't fix that by itself unless you deliberately wrap it in `db.transaction()`. Found two real instances doing this: `pulls/routes.ts`'s old inline PR-detail refresh (delete+insert `prFiles`, delete+insert `prCommits`, update `pullRequests` — 4 separate un-transacted calls) and `settings/routes.ts`'s old inline PUT handler (per-key upsert loop) — now `pulls/repository/pull.repo.ts`'s `replaceFilesAndCommits()` and `settings/repository.ts`'s `upsertMany()` respectively.
- 2026-10-02 — `AgentsService.list` maps rows with an explicit lambda because `toAgentDto(row, skillCount?)` gained a second param — `rows.map(toAgentDto)` would silently pass the array index as `skillCount`. Agent skill-link writes (`PUT/POST /agents/:id/skills`) run in one transaction with the version bump; the version only bumps when the ordered list of *enabled* linked skill ids changes (that list is exactly what the snapshot stores). (`server/src/modules/agents/repository.ts`)
- 2026-10-02 — Code shared between modules (e.g. `formatSkillBlock`, used by both `skills` and `reviews/run-executor`) lives in `server/src/modules/_shared/` — importing `../skills/helpers.js` from `reviews` would violate the onion no-cross-module rule AND drag `fflate` into the review path. (`server/src/modules/_shared/skill-prompt.ts`)

## Tool & Library Notes

- 2026-10-01 — Fastify + `fastify-type-provider-zod`: a request sent with NO body at all arrives as `req.body === null`, not `undefined`. If a route's Zod body schema needs to tolerate a fully-absent body (e.g. replacing a manual `Schema.parse(req.body ?? {})` with real schema-first validation), use `.nullish()`, not `.optional()` — `.optional()` only covers `undefined` and 422s on the real `null` case ("Expected object, received null"). Verified via `app.inject({method:'POST', url})` with no `payload`. (`server/src/modules/reviews/routes.ts:36` — `RunRequest.nullish()`)
- 2026-10-01 — Deriving a create/update request body from an entity Zod schema via `Entity.omit({...}).extend({...})`: if the entity field has `.default(v)` (e.g. `Agent.strategy`), that default survives into the omit-based CreateXBody — an omitted field there resolves to `v`, not `undefined`. `UpdateXBody = CreateXBody.partial()` then wraps it in another `.optional()`, which short-circuits before the inner default, so omitted fields correctly stay `undefined` on the UPDATE schema — but the CREATE schema itself won't, unless you re-declare that field as plain `.optional()` in the `.extend()` call instead of inheriting the entity's `.default()` version. (`server/src/modules/agents/routes.ts:39` — `CreateAgentBody`)
- 2026-10-02 — Run-log event kinds are a closed enum (`info`/`tool`/`result`/`error` in `RunEventKind`), so the L02 "skills" log line is emitted as `info`. `platform/errors.ts` has no Conflict/413 classes — the skills module defines `AppError` subclasses locally; the global handler maps them by `status`.
- 2026-10-02 — On Windows, Python `open(p,'w')` defaults to cp1252 + CRLF: an em dash becomes byte 0x97 (invalid UTF-8) and LF files flip to CRLF. Always pass `encoding='utf-8', newline=''` when scripting edits here.

- 2026-10-02 — Vitest: a `beforeAll`/`beforeEach` arrow that RETURNS a function (e.g. `beforeEach(() => mock.mockReset())` — `mockReset()` returns the mock) is treated as a cleanup hook and that function is CALLED after the test, with no args. With a `mockImplementation` that reads its args this surfaces as a baffling `Cannot read properties of undefined` from `callCleanupHooks`. Use a block body: `beforeEach(() => { mock.mockReset(); })`.
- 2026-10-02 — `db/seed.ts` already inserts `acme/payments-api` (and other repos); integration tests that insert their own repo row must use a different `full_name` or hit `repos_ws_fullname_uq`. (`server/test/conventions.it.test.ts`)
- 2026-10-02 — Conventions extractor: `GitClient.readFile` (`adapters/git/simple-git.ts`) joins the path onto the clone dir with NO traversal guard — anything model-supplied must pass `isSafeRepoPath` first (`modules/conventions/helpers.ts`). Grounding only lets evidence cite files that were actually sampled, and always stores the snippet read from the file, never the model's text.
